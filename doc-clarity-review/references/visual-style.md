# Visual Style — layout & export formats (MD → HTML/PDF/DOCX/XLSX)

Correct content with messy layout still gets skipped by readers. This file defines how to *write Markdown so that it renders well*, and how to export and check the final output.

## 1. Which format to export when

| What the user says / context | Export |
|---|---|
| Says nothing about format | `.md` only (the source). In the reply, mention in one line that PDF/DOCX/XLSX export is available. |
| "send to my boss", "send to the client", "print", "PDF" (VI: "gửi sếp", "gửi khách", "in") | `.md` + `.pdf` (A4) |
| "read on my phone", "view on mobile" (VI: "đọc trên điện thoại", "xem trên mobile") | `.md` + `.pdf` with `--page mobile`: page size ~108×192 mm, tables with ≥ 4 columns automatically become "label: value" cards |
| "Word", "docx", "so the team can keep editing" (VI: "để team sửa tiếp") | `.md` + `.docx` |
| Data dictionary, traceability matrix, findings list, metrics table — "Excel", "to filter/sort" (VI: "để lọc/sort") | `.md` + `.xlsx` (one sheet per table) |
| Several audiences | combine, e.g. `--to pdf,xlsx` |

Markdown is always the single source of truth: edit the content in the `.md` and re-render; never hand-edit the PDF/DOCX files.

## 2. Writing Markdown that renders well

**Document header**
```markdown
# <Document type>: <Name>
| Version | Date | Owner | Status |
|---|---|---|---|
| 0.1 | 2026-11-03 | <name> | Draft |
```
Vietnamese documents:
```markdown
# <Loại tài liệu>: <Tên>
| Phiên bản | Ngày | Owner | Trạng thái |
|---|---|---|---|
| 0.1 | 2026-11-03 | <tên> | Draft |
```
Place the metadata table **directly after the H1** — the theme renders it as a compact info strip. The table of contents is generated by the script when there are ≥ 6 H2 sections; do not write a table of contents by hand.

**Opening for approvers**: for a document going to a boss / client / stakeholder → directly after the metadata table, add a `> **Summary:**` block (Vietnamese documents: `> **Tóm tắt:**`) of 3–5 lines: what the document is, what decision they need to make, the 1–3 biggest risks/issues (point to IDs). Approvers often read only the first page.

**Headings**: write them for the reader, not the writer — "Data relationship diagram", not "Diagram (Mermaid)". Exactly one H1; numbered H2 `## 1. Overview` (Vietnamese: `## 1. Tổng quan`); H3 `### 1.1 ...`. Do not skip levels (H2 → H4).

**Tables**
- At most **6 columns**. A table with 7+ columns is cramped on portrait A4 and breaks on mobile → split it into 2 tables, or move long description columns into a list below.
- First column is the ID / short name; long description columns go last.
- Do not duplicate content just to serve another format (e.g. an appendix repeating every column only to get a flat Excel sheet) — unless the user needs Excel for filtering; in that case put that appendix at the end and state its purpose.
- Each cell ≤ ~40 words. Longer content → bullets below the table, referenced by ID.
- Do not break lines inside a cell with `<br>` more than 2 times.
- Column names, table names, endpoints, env vars inside cells: wrap in `backtick`.

**Markers and callouts**
- [TO CONFIRM: ...] (Vietnamese documents: [CẦN XÁC NHẬN: ...]) is written as plain text, *not* wrapped in backticks — the renderer gives it a yellow background so readers can scan for it quickly.
- Important notes use a blockquote (`> **Note:** ...`; Vietnamese documents: `> **Lưu ý:** ...`) — rendered as a light-blue block. At most 1–2 such blocks per section; more than that and they lose their emphasis.
- No decorative emoji in business documents.

**Mermaid diagrams**
- ≤ 15 nodes per diagram; larger diagrams → split by flow.
- Short labels (≤ 5 words); avoid the characters `;` `"` `{}` in labels — they break the syntax (most common error: `BEGIN; INSERT...` in a sequence diagram).
- Each diagram has one lead-in sentence directly before it saying what the diagram shows.

**Code blocks**: always specify the language (```` ```bash ````, ```` ```sql ````). Code lines ≤ 100 characters so they are not cut off in the PDF.

## 3. Render & check (visual QA)

```bash
python <skill-dir>/scripts/render_doc.py <doc.md> --to pdf,docx,xlsx --out-dir <output dir> --qa
# for reading on a phone:
python <skill-dir>/scripts/render_doc.py <doc.md> --to pdf --page mobile --out-dir <output dir> --qa
```
(`<output dir>` = output directory; `# for reading on a phone:` = for reading on a phone.)

Need both A4 (print/approval) and a mobile version: render twice into two directories, or rename the mobile file to `<name>-mobile.pdf`.

The script prints JSON containing `outputs`, `warnings`, `qa`. Then:

1. **Read the warnings**: Mermaid failed to render, table with ≥ 7 columns, missing tools (pandoc/Chrome/mmdc). Fix the `.md` source and re-render.
2. **Look at the page images** in `qa.preview_pages` (the Read tool displays images). At minimum look at page 1, the page with the largest table and the page with a diagram. Check:
   - accented characters display correctly (no empty boxes);
   - tables do not overflow the margin, the ID column does not break mid-value;
   - diagrams render as images and their labels are readable;
   - no near-empty pages caused by bad page breaks.
3. **DOCX**: if you need to inspect it, convert it to PDF to view images: `soffice --headless --convert-to pdf <file.docx>` then `pdftoppm -r 60 -png`.
4. **XLSX**: one sheet per table, with frozen header and filter; an index sheet ("Index"; "Mục lục" for Vietnamese documents) lists the sheets. Generated labels — figure captions, index sheet, Word footer "Page x/y" — follow the document language automatically. Check that sheet names are meaningful (taken from the nearest heading — put a clear heading before each table).

If the environment lacks a tool → the script skips that format and reports a warning; in that case tell the user plainly which formats were not exported; do not pretend they were.

## 4. Default design (for understanding, no need to change)

- Font: Inter (PDF/HTML), Arial (DOCX — available on every machine, full Vietnamese diacritics). Tabular figures in tables.
- One accent colour (blue `#2A4FB8`) for links/notes; yellow only for [TO CONFIRM] / [CẦN XÁC NHẬN]; red only for risks. Colour carries meaning, not decoration.
- A4, 16–20 mm margins, footer: document name + page number `x / y`. Table headers repeat when a table continues onto the next page.
